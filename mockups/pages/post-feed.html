Four copy boxes render on this page — two in the post above, one on Tom's comment, one on David's own. SPEC §7.2.4: an address on neither link list is delivered as an inert copy box showing the address in full and verbatim, never truncated in the value, never re-written, never resolved. None of them is flagged, because none of them is a problem — §7.2.4 forbids "a warning, an apology, error styling, or a 'this link is not approved' note beside it" here, and this post is the exact reader that rule exists to protect: an ordinary member linking to the rest of their own photographs. §16.3 names this control among the repeated ones needing distinct accessible names, "of which a single feed page may carry many", so each button reads "Copy" but is named for its own address through visually hidden text, in the same way the read-more folds above are — which is also what keeps 2.5.3's visible-label-matches-accessible-name rule true, since every name begins with the visible word. The single polite live region above is the copy confirmation §7.2.4 requires (4.1.3), composing partials/_status.html unchanged; its wording is invented (see mockups/CRIB.md §2 and mockups/NOTES.md). These mockups carry no scripts, so it is shown already populated, as if a reader had just used one of the four controls. The addresses themselves sit on the reserved documentation domains example.com, example.org and example.net, so none names a real site or implies anything about what either operator list actually carries.
