Settings

Assembled, not specified. No part of SPEC.md lays out a Settings page as one screen — this mockup gathers the individual settings scattered across several sections into a single page so the founder can see them together. Each section below names the SPEC section it was drawn from. Treat this page as closer to a proposal than a mockup of something already designed.

How many posts per page

Choose how many posts you'd like to see at a time in your feed and on any profile you visit. Nothing changes until you press Apply — picking a different number here doesn't do anything by itself.

SPEC §7.7.1: POSTS_PER_PAGE_DEFAULT = 20, from POSTS_PER_PAGE_OPTIONS = 20 / 40 / 60. This is a hard requirement, not a detail — "it takes effect on an explicit Apply, never on the change of a dropdown... a control that reloads the page the instant it is touched is a 3.2.2 failure." One setting, applying to the feed and every profile visited.

Theme and font

Choose how WeeBee looks for you — a font and a colour scheme.

We haven't decided what these will actually be called yet — the choices above are placeholders standing in for whatever list is eventually offered.

Turn this on and every page you visit — including a friend's profile — uses your own choices above instead of theirs, from the moment the page loads. A profile you visit can't turn this back off for you.

SPEC §9.1.1, §16.3: THEME_SET has no members named anywhere in either document — this page says so rather than inventing theme names, and the bracketed placeholder options above follow the same convention contact-card-editor.html already uses for an unspecified value. The "always use my own theme" viewer override is applied server-side at render, never as a client-side toggle a page could defeat — an implementation constraint stated here as plain copy, since it's a real promise about how the setting behaves, not a build note.

Following

You can always turn following off for one particular post, right there on the post — this only sets what happens the moment you comment.

SPEC §12.3: commenting turns following on by default; a visible per-post toggle turns it off, and this is the global default that decision falls back to.

Email notifications

Everything still shows up in your feed either way — this just adds a copy to your inbox for the same events.

SPEC §12 opening: delivery is in-feed, "plus optional email."

Change your login email

WeeBee will never email you a link to log in or reset your password — only a code you type in yourself.

We've sent a code to that new address. Enter it below, right here on this page, to finish the change.

SPEC §4.6, §4.6.1: the code goes to the new address, is typed back into this already-open settings page, never a link — and a notice is sent to the old address once the change completes. The checkable promise above is quoted verbatim from §4.6.1 and is shown "at the relevant touchpoints (login, reset, help)"; this page is one of them.

Export your data

Download a complete copy of everything you've put into WeeBee — your profile, your posts, comments you've written, your friend list, your groups, your contact card, and your photos — as plain files you can open anywhere.

SPEC §4.9: a complete copy in JSON plus image files. Serves GDPR compliance, a credible exit, and any future migration.

Delete your account

If you'd rather leave altogether, you can start that here. Your account deactivates right away — nobody else can see you anymore — and you get 30 days to change your mind by logging back in before everything is permanently erased.

Delete your account

SPEC §4.7: DELETE_GRACE_DAYS = 30. The deletion flow itself — the confirmation, the grace-period banner, cancelling it — is session M7's to build; this link is a forward reference to account-deletion.html, not yet built, in the same spirit as this track's other forward-referenced filenames since M1 (see mockups/CRIB.md §5).

Manage your groups

Groups are a private way to organize your own friends for quickly picking an audience. See groups.html.

Added here purely as a discoverability link this session introduces — no document places a "groups" entry inside settings, and the shared main navigation isn't touched by this session (see mockups/NOTES.md).
