Contact the operator

Beyond reporting something, there are ordinary things you might want to ask for: a new interest tag, a link allowed in posts, a bug fixed, an accessibility problem looked at, or just general feedback. One simple form covers all of them.

SPEC §13.5: "one simple submission form with a category dropdown," feeding the same operator queue as reports, separately categorized.

1. Filling out the form

Accessibility problems are looked at before feature requests.

Categories verbatim from SPEC §13.5: Hashtag suggestion · External service request · Bug report · Accessibility problem · General feedback / feature request. Submissions are private (you to the operator only) and rate-limited, with no notification machinery attached.

2. After you send it

Thanks — this has gone into a queue the operator reads in batches. There's no reply, and there's nothing to check on here: if it leads to a change, you'll simply see it appear where it belongs — a new option in a picker, a new link allowed in posts. There's no set schedule for when that happens.

SPEC §13.5, v1.21: "submissions are read in batches, no reply is sent, and an accepted change simply appears where it belongs." No interval is ever stated to users, and this mockup deliberately invents no status page, no "pending" state, and no per-submission outcome — all of which §13.5 rules out on purpose.
