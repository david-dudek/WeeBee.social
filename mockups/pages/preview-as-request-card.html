The card, as a recipient would see it

Per §9.1's field table, this card is a deliberate mix of frozen and live fields — "a security boundary, not a rendering detail." Each field below is labelled with its source rather than leaving the split to be inferred.

David Dudek (formerly Dave Dudek)

Profile photo — frozen at send time (§5.2). A stored copy from the moment this request would be sent, not a pointer to the current image; a later photo change never reaches a card already delivered. Display name — live, rendered through the shared helper (§4.5.1); names are never stored on content, so the dual "(formerly …)" form here tracks David's real, current transition state, not whatever it was at send time. Report action — live, targeting David's current profile rather than the frozen snapshot (§13.2) — it renders here because it is exactly what a real recipient would see on this card, not because David could ever see it on his own profile otherwise.

Short bio

Dad, hiker, mediocre baker who peaked at loaf six. Up for coffee or a walk most weekends. Find the rest of the story at weebee dash social dot com.

Frozen at send time (§5.2). The same reason as the photo: a later bio edit does not rewrite a request already sent. This is also the field REQUEST_HOLD_AFTER_PROFILE_CHANGE_HOURS (§13.6) holds sending after — the card is frozen at the far end and the sender is held at the near end, so neither a stale card nor a freshly rewritten one can exist.
